## When a task is complete
- Add a bullet to `CHANGELOG.md` (create if missing): what changed and why.
  Keep it to 2-4 lines, not a diff.
- If the task involved a process worth repeating, write a short tutorial
  in `docs/tutorials/<task-name>.md` — steps + reasoning, written for someone
  learning it for the first time.
- "Task complete" means a discrete piece of work is done (a feature, a fix,
  a refactor) — not every individual file edit along the way.

## Educational documentation

Maintain a `documentation.md` file in this directory as an educational resource: explain this project's architecture, key techniques/libraries, and non-obvious design decisions in accessible terms, since the user is not deeply familiar with the engineering here. Create it if missing, and update it after meaningful changes. See the root `CLAUDE.md` (one level up) for full guidance.
